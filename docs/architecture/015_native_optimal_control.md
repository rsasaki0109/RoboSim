# 015 — Native multi-contact optimal control (DDP)

## Status

Implemented. Contact dynamics, a contact sequence, impacts, and an FDDP warm
start are in place; contact-sequence search and analytical derivatives are
follow-ups.

## Context

The legged stack can track a given center-of-mass trajectory (`rne_legged`) with
a whole-body controller (`rne_wbc`), but agile maneuvers such as jumps, hurdles,
and parkour need the *maneuver itself* to be generated by trajectory
optimization over a contact sequence. The reference tool is Crocoddyl: a
multi-contact optimal-control library whose DDP/FDDP solvers produce gaits,
jumps, and flips in milliseconds, built on Pinocchio's analytical rigid-body
derivatives.

Core crates must not depend on Crocoddyl, Pinocchio, RBDL, or any external
dynamics/optimal-control library, and the result must stay deterministic and
headless.

## Decision

Add `rne_oc`, a backend-neutral optimal-control crate.

The first slice owns:

- `DiscreteDynamics`/`ShootingDynamics` and a **node-aware `CostModel`** for a
  shooting problem `x_{k+1} = f(x_k, u_k)`, plus a `PhaseCostSchedule` that
  gives each phase its own quadratic reference (the Crocoddyl action-model
  analogue);
- a diagonal `QuadraticCost` with analytic derivatives, split into running and
  terminal parts;
- `dynamics_derivatives`, Richardson-extrapolated central-difference Jacobians
  of the dynamics (`O(epsilon^4)` accuracy), which markedly improves the gradient
  quality through contact-rich rollouts;
- `solve`, a deterministic DDP with Levenberg–Marquardt regularization on the
  control Hessian and a backtracking line search that only accepts feasible
  rollouts that reduce the cost; setting `keep_gaps_open` switches it to an FDDP
  warm start that opens dynamics gaps early and then polishes with DDP;
- `ArticulatedDynamics`, which integrates one step of the native
  `rne_dynamics::forward_dynamics` with semi-implicit Euler (`[q, qd]` state,
  actuated-joint torque control);
- `ConstrainedArticulatedDynamics`, which integrates the rigid-contact KKT
  solution from `rne_dynamics::constrained_forward_dynamics` so the active
  points neither accelerate nor separate;
- `ContactSequenceDynamics`, a node-dependent shooting model whose active
  contact set changes per phase, exposed through the `ShootingDynamics` trait.

The crate owns no physics backend, renderer, contact solver, or external
library.

### Algorithm

Each iteration linearizes the dynamics and cost at the current trajectory,
computes the action-value derivatives `Qx, Qu, Qxx, Qux, Quu`, and solves the
local quadratic for the feedforward `k = -Quu^-1 Qu` and feedback `K =
-Quu^-1 Qux`. The value function is updated as `Vx = Qx + Qux^T k` and `Vxx =
Qxx - Qux^T Quu^-1 Qux`. A line search applies `u = u_bar + alpha k + K (x -
x_bar)`, rolls out the dynamics, and accepts the first cost-decreasing step;
the regularization grows on failure and shrinks on success.

## Dependency boundary

`rne_oc` may depend on `rne_dynamics`, `rne_robot`, `rne_world`, `rne_ecs`, and
`rne_math`. It must not depend on a renderer, physics backend, ROS 2, or an
external optimal-control/dynamics library.

## Validation

- A double integrator reaches `p = 1` with the terminal cost small, and the
  solver is bit-for-bit deterministic.
- A single-revolute pendulum swings up to `+pi/2` from `-pi/2` under native
  `ArticulatedDynamics`, using only the DDP solver and `rne_dynamics`.
- A floating body with three point contacts stays put under
  `ConstrainedArticulatedDynamics`, and a two-phase `ContactSequenceDynamics`
  holds the body while a contact is active and lets it fall once the contact
  set is emptied.
- An **impact reset** (`rne_dynamics::impulse_velocity`) arrests a falling
  body's contact-point velocity to zero, and `ContactSequenceDynamics` applies
  it automatically when a phase adds contacts.
- **FDDP** (`DdpConfig::keep_gaps_open`) converges from an infeasible
  straight-line guess; the solver then projects the controls onto a feasible
  rollout and polishes with standard DDP, so the returned trajectory satisfies
  the dynamics to `1e-3`.
- `examples/108_go2_jump_opt` optimizes a Unitree **Go2 jump** over a fixed
  crouch → push → flight contact sequence with per-phase action costs and FDDP:
  with control limits of ±23.7 Nm the floating base reaches a **0.372 m apex**,
  ends at the target with near-zero velocity, the torque saturates exactly at
  the actuator limit, the joints stay natural (`[-3.31, 1.96]` rad), and the
  contact dynamics are satisfied to machine precision. This is the first
  **actuator-realizable** jump produced by the native stack.

## Limitations and follow-ups

- **Contact-sequence search.** The phase schedule is still caller-provided;
  automatic discovery is not implemented.
- **Analytical derivatives.** Richardson-extrapolated central differences fixed
  the conditioning of the jump, but a Pinocchio-equivalent analytical
  RNEA/CRBA derivative layer would be faster and more accurate.

- **Search over contact sequences.** The phase schedule is still caller-provided;
  automatic contact-sequence discovery is not implemented.
- **Analytical derivatives.** Central differences are correct but slow; a
  Pinocchio-equivalent analytical RNEA/CRBA derivative layer is the natural
  `rne_dynamics` extension.
- **Inequality constraints.** Box (control) constraints are implemented; the
  friction cone and general state inequality constraints are not.

## Consequences

- Maneuvers can now be generated by trajectory optimization that reuses the
  native forward dynamics, deterministically and without external libraries.
- The remaining gap to a Crocoddyl-class toolbox is contact-sequence search and
  analytical derivatives — both scoped extensions rather than new foundations.
