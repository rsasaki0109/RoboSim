# 015 — Native multi-contact optimal control (DDP)

## Status

Implemented (first slice). FDDP gap handling, contact dynamics, and analytical
derivatives are follow-ups.

## Context

The legged stack can track a given center-of-mass trajectory (`rne_legged`) with
a whole-body controller (`rne_wbc`), but agile maneuvers such as jumps, hurdles,
and parkour need the *maneuver itself* to be generated by trajectory
optimization over a contact sequence. The reference tool is Crocoddyl: a
multi-contact optimal-control library whose DDP/FDDP solvers produce gaits,
jumps, and flips in milliseconds, built on Pinocchio's analytical rigid-body
derivatives.

Core crates must not depend on Crocoddyl, Pinocchio, RBDL, or any external
dynamics/optimal-control library, and the result must stay deterministic and
headless.

## Decision

Add `rne_oc`, a backend-neutral optimal-control crate.

The first slice owns:

- `DiscreteDynamics` and `CostModel` traits for a shooting problem `x_{k+1} =
  f(x_k, u_k)`;
- a diagonal `QuadraticCost` with analytic derivatives, split into running and
  terminal parts;
- `dynamics_derivatives`, central-difference Jacobians of the dynamics;
- `solve`, a deterministic DDP with Levenberg–Marquardt regularization on the
  control Hessian and a backtracking line search that only accepts feasible
  rollouts that reduce the cost;
- `ArticulatedDynamics`, which integrates one step of the native
  `rne_dynamics::forward_dynamics` with semi-implicit Euler (`[q, qd]` state,
  actuated-joint torque control).

The crate owns no physics backend, renderer, contact solver, or external
library.

### Algorithm

Each iteration linearizes the dynamics and cost at the current trajectory,
computes the action-value derivatives `Qx, Qu, Qxx, Qux, Quu`, and solves the
local quadratic for the feedforward `k = -Quu^-1 Qu` and feedback `K =
-Quu^-1 Qux`. The value function is updated as `Vx = Qx + Qux^T k` and `Vxx =
Qxx - Qux^T Quu^-1 Qux`. A line search applies `u = u_bar + alpha k + K (x -
x_bar)`, rolls out the dynamics, and accepts the first cost-decreasing step;
the regularization grows on failure and shrinks on success.

## Dependency boundary

`rne_oc` may depend on `rne_dynamics`, `rne_robot`, `rne_world`, `rne_ecs`, and
`rne_math`. It must not depend on a renderer, physics backend, ROS 2, or an
external optimal-control/dynamics library.

## Validation

- A double integrator reaches `p = 1` with the terminal cost small, and the
  solver is bit-for-bit deterministic.
- A single-revolute pendulum swings up to `+pi/2` from `-pi/2` under native
  `ArticulatedDynamics`, using only the DDP solver and `rne_dynamics`.

## Limitations and follow-ups

- **FDDP / infeasible warm start.** The current solver requires a feasible
  initial rollout and accepts only cost-decreasing feasible steps. Crocoddyl's
  FDDP keeps dynamics gaps open early, which is what makes contact-rich,
  highly dynamic maneuvers converge from a coarse guess.
- **Contacts and impulses.** There is no contact-sequence model yet (rigid
  contact acceleration constraints and impact reset maps). This is the next
  required piece for gaits and jumps.
- **Analytical derivatives.** Central differences are correct but slow; a
  Pinocchio-equivalent analytical RNEA/CRBA derivative layer is the natural
  `rne_dynamics` extension.
- **Inequality constraints.** No box/control limits or friction cone yet
  (Box-FDDP / interior-point tier).

## Consequences

- Maneuvers can now be generated by trajectory optimization that reuses the
  native forward dynamics, deterministically and without external libraries.
- The remaining gap to a Crocoddyl-class toolbox is contacts, impulses, and
  derivatives — all of which are scoped extensions rather than new foundations.
